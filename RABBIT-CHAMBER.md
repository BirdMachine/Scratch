# 🐰🕳️ RABBIT CHAMBER // FURNITURE KIT 04

> **The furniture is now learning where native content wants to live.**

This chamber focuses on components that are useful *because they leave something empty*: screenshot sockets, inspection tabs, material adapters, host-substrate displays, and physical docks for release artifacts.

---

## 01 // SCREENSHOT CORNER SOCKETS

<img src="furniture/42-screenshot-corners.svg" width="100%">

The middle is intentionally missing.

Drop an ordinary GitHub image immediately below this, and the four corners should make the screenshot feel physically installed without wrapping or rasterizing it.

![placeholder screenshot](https://dummyimage.com/1200x600/22313a/89fff0&text=NATIVE+SCREENSHOT+WOULD+LIVE+HERE)

The useful pattern is:

`corner socket → native image → maybe a tiny rail/feet component`

No bespoke screenshot composite required.

## 02 // INSPECTION TABS

<img src="furniture/43-inspection-tabs.svg" width="100%">

Small numbered furniture gives us **cheap recurring structure**. These can precede subsections, screenshot sets, architecture layers, or install stages.

Unlike giant headers, tabs can repeat often without exhausting the page.

### 01 / INPUT

Normal Markdown.

### 02 / CORE

Still normal Markdown.

The visual system remains outside the information.

## 03 // MATERIAL ADAPTER

<img src="furniture/44-material-adapter.svg" width="100%">

This one exists because our component system is getting diverse enough that different visual families need to **physically meet**.

Left: machined metal. Right: translucent Aero-ish glass. Middle: impossible optical coupler.

That gives us a reusable excuse for changing material systems mid-page without it feeling arbitrary.

> A README can have subsystems instead of one global theme.

---

## 04 // EMPTY GLASS DISPLAY

<img src="furniture/45-empty-glass-display.svg" width="100%">

This is almost nothing: transparent pane, spectral edge, highlight.

The important surface is whatever GitHub theme is visible through it.

### Host-rendered content lives *after* the display

The next step is to split this into **top / left / right / bottom pieces** so native Markdown can literally occupy the perceived glass screen.

Dark mode becomes smoked glass. Light mode becomes clear acrylic. Same furniture, different apparent material density.

---

## 05 // RELEASE DOCK

<img src="furniture/46-release-dock.svg" width="100%">

Instead of treating a release link as a badge/button, the README can present releases as a **hardware bay**.

The actual link can stay ordinary and truthful:

[Latest release →](../../releases/latest)

The dock is just the fiction around it.

Future variants: translucent game cartridge, MiniDisc, lab sample cassette, bizarre optical puck, cassette with a tiny holographic seal.

# 🧠 RABBIT CHAMBER FINDINGS

We now have enough primitives to describe several reusable page grammars:

### Instrument page

`identity plate → status ribbon → tabs → rack ears → native content → feet → rear I/O`

### Aero glass page

`glass hero → optical nav → empty display → native Markdown → spectral continuity tails`

### Lab/specimen page

`inspection tabs → specimen rail → native image table → warning brackets → service labels`

### Hybrid machine

`metal chassis → material adapter → glass subsystem → fluid reservoir → release dock`

The fun bit is that **one project does not need one material family**. The adapter legitimizes transitions.

# 🐇 NEXT BURROW

I want to breed:

- actual four-piece empty-display hardware around a live Markdown center,
- left/right vertical rails with a native center column,
- tiny micro-furniture sheet: screws, lamps, stickers, serial plates, calibration ticks,
- screenshot feet / LCD lower bezel to pair with the corner sockets,
- linked tab variants where each physical-looking tab is genuinely clickable,
- cable tails in several colors/materials for continuity crimes,
- a complete **README skeleton/template** showing where these pieces slot into a real project without overwhelming the docs,
- alternate skins with identical geometry so one README layout can swap materials without rewriting structure,
- a deliberately elegant restrained kit and a deliberately deranged max-chroma kit.

> **A component system becomes real when the pieces can be recombined without remembering why they were invented.**

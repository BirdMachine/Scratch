# 🐇🔩 ILLEGAL GITHUB FURNITURE — KIT 03

> **The empty space is now a component.**

Kit 02 established furniture as punctuation. Kit 03 gets more invasive: instead of drawing content, these pieces are designed around **holes where native GitHub must remain alive**.

---

## 01 // TERMINAL BEZEL WITH A REAL TERMINAL INSIDE

<img src="furniture/36-terminal-top.svg" width="100%">

```bash
$ ./ignite.sh --reality=optional
mounting README............. ok
probing chromatic bus....... suspicious
installing bird.dll......... 100%
markdown remains selectable. excellent.
```

<img src="furniture/37-terminal-bottom.svg" width="100%">

This is the useful trick from the rack experiment pushed further. The **code block is the display**. GitHub owns syntax highlighting, selection, copying and wrapping; our SVG only supplies the imaginary industrial object around it.

In a real project this can frame install commands without sacrificing them to rasterized decoration.

## 02 // WARNING BRACKETS

<img src="furniture/38-warning-brackets.svg" width="100%">

> [!WARNING]
> This warning is native Markdown. The furniture doesn't know what it says and frankly seems worried about that.

The brackets are deliberately mostly absence. They establish a warm amber/vermillion hazard region, while GitHub renders the semantic warning itself.

This suggests **semantic furniture**: decoration selected according to the native element immediately following it.

## 04 // CONTINUITY TAIL

<img src="furniture/40-optical-tail-left.svg" width="100%">

### Several paragraphs may now happen.

The cable above visibly leaves the composition without terminating. That creates a tiny unresolved visual debt.

A later component can enter from the opposite edge using the same cyan glow, amber branch and magenta coupler. They never physically touch. **Scroll distance becomes cable length.**

This is useful precisely because it should *not* happen constantly. One or two unresolved signals across a long README can make the entire page feel spatially continuous.

---

## 05 // PROJECT IDENTITY AS AN OBJECT

<img src="furniture/41-enamel-identity.svg" width="100%">

Badges are labels attached to a project. This reverses the relationship: the **project name itself becomes a manufactured part**.

This specimen is warm vermillion/coral + deep petroleum teal + cream enamel. No purple required. It feels somewhere between laboratory equipment, a 1970s appliance badge, arcade hardware and an object that should have been screwed to a submarine.

A family of these can give each project its own material identity without changing the underlying README grammar.

# 🧠 DESIGN RULE DISCOVERED: OPEN COMPONENTS

The strongest furniture so far has a peculiar property: **it is visibly incomplete without the host page**.

Closed component:

`[ SVG contains title + body + diagram + labels ]`

Open component:

`[ SVG top ] → native Markdown → [ SVG bottom ]`

or

`[ left physical object ] → enormous intentional absence → [ right physical object ]`

The latter recruits GitHub itself as part of the rendering stack. Dark/light theme, text wrapping, accessibility, links, copyable code and responsive behavior stop being enemies and become material properties.

# 🧬 NEXT BREEDING CHAMBER

Things worth mutating next:

- screenshot **corner sockets** that only occupy four corners;
- split left/right vertical rails assembled with Markdown tables;
- tiny numbered **inspection tabs** for subsections;
- cable continuation pairs with multiple material/color identities;
- optical fibers that apparently pass *behind* a native screenshot;
- release cartridges where actual release links sit beside the physical cartridge;
- a README top assembly composed from interchangeable hero plate + status strip + nav controls;
- micro furniture sheets: screws, lamps, calibration bars, warning stickers, tiny engraved labels;
- **material adapters**: one end Aero glass, the other machined metal, implying two visual families physically connect;
- empty glass frames where GitHub dark/light mode literally becomes the screen color;
- a vertical exploded-device README where each major documentation section is a different physical layer.

> **Do less rendering. Manufacture better holes.**
